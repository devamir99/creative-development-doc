# فنر، اینرسی، تکانه و ردشدن از هدف

## اول ببین

<SpringPlayground />

فنر فقط نمی‌رسد. رد می‌شود، برمی‌گردد و انرژی از دست می‌دهد. آن ردشدن اطلاعات وزن و کشسانی است.

## مقدمه

**اینرسی** مقاومت در برابر تغییر است. **تکانه (Momentum)** حرکت حمل‌شده است. مدل **فنر** جسم را با سختی و میرایی به‌سمت هدف می‌کشد. **ردشدن از هدف (Overshoot)** وقتی رخ می‌دهد که انرژی آن را از مقصد جلوتر ببرد.

## مدل ذهنی

| ویژگی | مقدار بالاتر حس می‌شود |
|---|---|
| سختی (Stiffness) | کشش سریع‌تر به هدف، تندتر |
| میرایی (Damping) | نوسان کمتر، نشست سریع‌تر |
| جرم (Mass) | سنگین‌تر، کندتر در تغییر |
| سرعت اولیه | حمل بیشتر |

## چرا مهم است

حرکت فیزیکی رابط را پاسخگو و اشیاء را مادی حس می‌کند. ولی فنر افراطی روی هر دکمه تازگی می‌شود نه زبان.

## پارامترها

| پارامتر | اثر |
|---|---|
| سختی/تنش | قدرت جذب |
| میرایی/اصطکاک | اتلاف انرژی |
| جرم | مقاومت |
| سرعت | انرژی شروع |
| محدودکننده ردشدن | از افراط شکستن layout جلوگیری می‌کند |

## کاربردهای عملی

۱. **رهاسازی درگ:** تکانه ادامه می‌دهد، بعد فنر می‌نشیند.
۲. **باتم‌شیت:** فنر قفل لمسی می‌سازد.
۳. **پیکربند محصول:** قطعات با نشست خفیف اسنپ می‌شوند.
۴. **برند بازیگوش:** ردشدن کشسان‌تر.

## پیاده‌سازی

GSAP برای موارد ساده `elastic.out` و ایزهای شبیه فیزیک دارد. برای درگ تعاملی از سیستم فنر/فیزیک اختصاصی استفاده کن و سرعت را محدود کن.

```ts
gsap.to(el, { x: 300, duration: 1, ease: "elastic.out(1, 0.45)" });
```

ویژگی‌های layout را با ردشدن بزرگ متحرک نکن اگر باعث reflow می‌شود.

## خطاهای رایج

- Bounce روی تأییدهای جدی، خطا و پرداخت
- فنرهایی که خیلی طولانی نوسان می‌کنند
- فیزیک فنر متفاوت روی هر کامپوننت
- نادیده‌گرفتن قطع‌پذیری وقتی کاربر عنصر در حال حرکت را می‌گیرد

## دسترس‌پذیری

فنرها هنوز حرکت‌اند. کاربران حرکت کاهش‌یافته باید جایگزین آنی یا محو کوتاه بگیرند.

## کی استفاده کنی / نکنی

برای درگ، رهاسازی، قفل، تأکید بازیگوش استفاده کن. برای ورود داده متراکم، اقدامات مخرب و ناوبری تکراری پرهیز کن.

## نکات کلیدی

- ردشدن انرژی را منتقل می‌کند.
- میرایی تصمیم می‌گیرد انرژی چقدر سریع بمیرد.
- محصول به یک زبان فنر نیاز دارد، نه کشسانی تصادفی.

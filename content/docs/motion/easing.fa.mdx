# ایزینگ (منحنی حرکت)

## اول ببین

همان فاصله و مدت روی باند نورپردازی‌شده: مکعب زرد توپر = ایزینگ انتخاب‌شده، مکعب سیمی = خطی. نمودار منحنی مسابقه سه‌بعدی را آینه می‌کند. منحنی را عوض کن و **پخش دوباره** را بزن.

<EasingPlayground />

## مقدمه

**ایزینگ** یعنی حرکت *درون* یک مدت چطور پیشرفت می‌کند. زمان‌بندی جواب می‌دهد «چقدر طول بکشد؟» ایزینگ جواب می‌دهد «سرعت در طول مسیر چطور عوض شود؟»

با `ease: "none"` (خطی)، پیشرفت متناسب با زمان است. بیشتر حرکت‌های واقعی خطی نیستند: اجسام شتاب می‌گیرند، کند می‌شوند، رد می‌شوند یا آرام می‌نشینند.

## چرا مهم است

همان مدت فقط به‌خاطر منحنی می‌تواند نرم، سریع، سنگین یا بازیگوش حس شود. اول [زمان‌بندی](./timing.mdx) را مسلط شو.

## توضیح بصری

| خانواده | حس |
|---|---|
| خطی | مکانیکی |
| Ease-in | شروع آرام، پایان سریع |
| Ease-out | شروع سریع، فرود نرم (بیشتر UI) |
| Ease-in-out | نرم در هر دو سر |
| Back / bounce | بازیگوش — راحت می‌شود زیاده‌روی کرد |

هنگام مقایسه منحنی‌ها مدت و فاصله را ثابت نگه دار.

## پارامترها

| پارامتر | نقش در این دمو |
|---|---|
| `ease` | رشته ایزینگ GSAP (پیش‌فرض‌های بالای صحنه) |
| `duration` | ساعت مشترک هر دو مسیر (`0.4` / `0.8` / `1.2`) |
| فاصله (`x: 200`) | ثابت، تا فقط منحنی شخصیت را عوض کند |
| کنار هم | A = ایزینگ انتخاب‌شده · B = مرجع خطی |
| نمودار منحنی | پیشرفت نسبت به زمان برای ایزینگ انتخاب‌شده |

## مثال‌های عملی

۱. **ورود مودال/دراور** — مدت کوتاه + ease-out قوی. ظاهر سریع، نشست نرم؛ کاربر بدون صبر می‌خواند.
۲. **آشکارسازی هیروی صفحه** — مدت بلندتر + ease-in-out ملایم یا ease-out نرم. منحنی «سینمایی» را بیشتر از ثانیه خام حمل می‌کند.
۳. **تاگل/چک‌باکس** — مدت خیلی کوتاه + ease-out ملایم (یا نزدیک خطی). ردشدن اینجا حس اسباب‌بازی می‌دهد، نه کنترل.
۴. **تکان تأکیدی (بج، لایک)** — یک back/overshoot کوچک اختیاری. اگر همه‌چیز رد شود، هیچ‌چیز خاص حس نمی‌شود.

## پیاده‌سازی

ساده‌ترین ابزار درست:

۱. **CSS** — `transition-timing-function` / `animation-timing-function` (`ease`، `ease-out`، `cubic-bezier(...)`).
۲. **GSAP** — `ease` روی tweenها (`"power2.out"`، `"none"`، سفارشی).

```js
// منحنی‌ها را با مدت و فاصله یکسان مقایسه کن
gsap.to(".element", {
  x: 240,
  duration: 0.8,
  ease: "power2.out", // امتحان کن "none", "power2.in", "power2.inOut"
});
```

```css
.element {
  transition:
    transform 0.8s cubic-bezier(0.16, 1, 0.3, 1); /* شبیه ease-out */
}
```

هنگام یادگیری ایزینگ‌های نام‌دار GSAP یا بزیه‌های شناخته‌شده را ترجیح بده. بزیه سفارشی قدرتمند است؛ ناهماهنگ‌کردنش در یک محصول هم راحت است.

## نکات کارایی

- ریاضی ایزینگ ارزان است. هزینه چیزی است که متحرک می‌کنی (layout، فیلتر، درخت بزرگ).
- ویژگی‌های دوستدار کامپوزیتور را ترجیح بده (`transform`، `opacity`).
- حرکت کاهش‌یافته: مدت کوتاه‌تر، منحنی ساده‌تر یا بدون حرکت — زیر `prefers-reduced-motion: reduce` bounce را «درست» نکن.

## خطاهای رایج

- انتخاب ایزینگ فانتزی قبل از درست‌شدن مدت
- bounce/elastic روی UI مسیر حیاتی (فرم، ناوبری)
- ایزینگ متفاوت روی هر عنصر بدون زبان مشترک
- مقایسه ایزینگ‌ها همراه با تغییر مدت یا فاصله
- فرض اینکه «منحنی بیشتر» یعنی «پریمیوم‌تر»

## کی استفاده کنی / نکنی

**استفاده عمدی کن وقتی:**

- روی مدت واضح، وزن، نشست یا شخصیت می‌خواهی
- چند حرکت باید یک سیستم حس شوند (خانواده ایز مشترک)
- مقایسه کنار هم چشم را آموزش می‌دهد (دموهای آزمایشگاه)

**از ایزینگ پرزرق‌وبرق پرهیز کن وقتی:**

- کاربر منتظر انیمیشن است
- تنظیمات دسترس‌پذیری حرکت کمتر می‌خواهد
- حرکت یک تأیید کوچک است
- هنوز زمان‌بندی را درست نکرده‌ای

## نکات کلیدی

- ایزینگ زمان → پیشرفت را نگاشت می‌کند؛ زمان‌بندی مدت اجرای آن نگاشت را تعیین می‌کند.
- منحنی‌ها را با مدت و فاصله ثابت مقایسه کن.
- Ease-out اسب کاری پیش‌فرض ورودهای UI است؛ خطی ابزار آموزشی و انتخاب نادر تولیدی است.
- ردشدن و bounce ادویه‌اند، نه غذا.
- یک واژگان ایز کوچک و مشترک برای محصولت بساز — بعد عمداً بشکن.

## تمرین

یک مدت (مثل `0.8s`) و یک فاصله انتخاب کن. با `none`، `power2.in`، `power2.out` و `power2.inOut` متحرک کن. برای هر منحنی یک صفت بنویس. آن فهرست را کنار واژگان زمان‌بندی‌ات نگه دار.

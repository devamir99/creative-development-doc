# مبانی Three.js، React Three Fiber و Drei

## اول ببین

<RaycastPlayground />

این صحنه پشته هسته را دارد: Canvas، دوربین، نورها، مش‌ها، متریال‌ها و تعامل اشاره‌گر.

## گراف صحنه

```text
Renderer / Canvas
└── Scene
    ├── Camera
    ├── Lights
    ├── Mesh = Geometry + Material
    ├── Groups (transform hierarchy)
    └── Effects / controls
```

## واژگان هسته

| مفهوم | معنا |
|---|---|
| Geometry | داده شکل (جعبه، کره، buffer geometry سفارشی) |
| Material | پاسخ سطح به نور |
| Mesh | هندسه + متریال در صحنه |
| Group | ظرف تبدیل |
| Texture | تصویر/داده اعمال‌شده روی متریال |
| Render loop | چرخه به‌روزرسانی فریم |
| Frustum | حجم دید دوربین |
| Raycaster | انتخاب اشاره‌گر در سه‌بعدی |

## مدل ذهنی R3F

React Three Fiber اجازه می‌دهد اشیای Three به‌صورت کامپوننت React توصیف شوند. React گراف صحنه را reconcile می‌کند، اما به‌روزرسانی‌های حساس به کارایی باید در `useFrame` یا رویدادها رخ دهند بدون رندر دوبارهٔ غیرضروری React.

Drei کمک‌کننده‌ها می‌دهد: دوربین‌ها، کنترل‌ها، محیط‌ها، لودرها و انتزاع‌های رایج. کمک‌کننده‌ها جادو نیستند؛ یاد بگیر چه شیء Three می‌سازند.

## چرا مهم است

تقریباً هر تجربه سه‌بعدی خلاقانه وب به این‌ها خلاصه می‌شود: ترکیب صحنه، دوربین، نور، متریال، تعامل و بودجه رندر.

## پارامترهایی که اول مهم‌اند

| پارامتر | اثر |
|---|---|
| DPR | تیزی در برابر هزینه GPU |
| Camera FOV/position | قاب‌بندی |
| Material roughness/metalness | واقع‌گرایی سطح |
| Light intensity/shadow | فرم و حال‌وهوا |
| Geometry segments | کیفیت سیلوئت و هزینه |
| Frameloop | همیشه رندر یا رندر هنگام تقاضا |

## کاربردهای عملی

۱. **بازبین محصول:** یک گروه محصول، کنترل اوربیت، هات‌اسپات.
۲. **صحنه هیرو:** محیط low-poly، مسیر دوربین، مه.
۳. **پیکربند:** تعویض متریال/هندسه با وضعیت.
۴. **مجسمه داده:** هندسه تولیدشده از داده.

## پیاده‌سازی

```tsx
<Canvas dpr={[1, 1.75]} frameloop="demand">
  <PerspectiveCamera makeDefault position={[0, 1.5, 5]} fov={40} />
  <ambientLight intensity={0.3} />
  <directionalLight position={[3, 5, 2]} />
  <mesh>
    <boxGeometry args={[1, 1, 1]} />
    <meshStandardMaterial color="#fafa05" roughness={0.45} />
  </mesh>
</Canvas>
```

## خطاهای رایج

- به‌روزرسانی state ری‌اکت در هر فریم برای حرکت پیوسته
- چند canvas در یک صفحه
- DPR بدون سقف روی صفحه‌های 4K
- فراموشی dispose هنگام ساخت imperative هندسه/متریال
- بارگذاری صحنه سه‌بعدی کامل برای یک آیکون تزئینی

## کارایی

برای صحنه‌های ایستا/تعامل‌محور از `frameloop="demand"` استفاده کن، متریال/هندسه را دوباره به‌کار ببر، مدل/بافت را فشرده کن، و صحنه‌های پایین صفحه را lazy-load کن.

## کی استفاده کنی / نکنی

وقتی وضعیت declarative صحنه مهم است، R3F را داخل محصولات React استفاده کن. وقتی استقلال از فریم‌ورک یا مثال‌های خیلی کوچک مهم است، Three وانیلا. جایی که CSS/SVG بهتر پیام می‌دهد، از WebGL پرهیز کن.

## نکات کلیدی

- Mesh = هندسه + متریال.
- R3F یک رندرر برای Three است، نه موتور جدا.
- DPR، نورها، سایه‌ها و draw callها را بودجه کن.

# Raycasting، تعامل ماوس و هات‌اسپات سه‌بعدی

## اول ببین

<RaycastPlayground />

Hover بازخورد را عوض می‌کند. کلیک انتخاب را قطعی می‌کند. این تمایز در رابط‌های محصول مهم است.

## مقدمه

**Raycasting** یک پرتو خیالی از دوربین از میان اشاره‌گر به داخل صحنه می‌اندازد و تقاطع‌ها را گزارش می‌دهد. انتخاب شیء، هات‌اسپات، صفحه درگ، شلیک، ارتفاع زمین و UI سه‌بعدی را قدرت می‌دهد.

## وضعیت‌های تعامل

| وضعیت | بازخورد | معنا |
|---|---|---|
| Hover | برجسته‌سازی، نشانگر pointer | «می‌شود استفاده کرد» |
| Active/press | تغییر مقیاس/رنگ | «ورودی گرفته شد» |
| Selected | تأکید پایدار | «این فعلی است» |
| Disabled | خاموش، بدون نشانگر pointer | «در دسترس نیست» |
| Drag | شیء از صفحه پیروی می‌کند | دست‌کاری مستقیم |

## چرا مهم است

سه‌بعدی بدون انتخاب فیلم است. انتخاب صحنه‌ها را به رابط تبدیل می‌کند: پیکربندها، شوروم‌ها، بازی‌ها، نقشه‌ها و کاوشگرهای آموزشی.

## پارامترها/مفاهیم

| مفهوم | نقش |
|---|---|
| Pointer NDC | اشاره‌گر تبدیل‌شده به مختصات صحنه -1..1 |
| Raycaster | تقاطع‌ها را محاسبه می‌کند |
| Intersect object list | چه چیزهایی قابل انتخاب‌اند |
| Event propagation | کدام شیء تو در تو برنده می‌شود |
| Invisible hit area | هدف بزرگ‌تر/آسان‌تر از نشانگر بصری |
| Drag plane | سطحی برای تبدیل اشاره‌گر به حرکت سه‌بعدی |

## کاربردهای عملی

۱. **هات‌اسپات محصول:** کلیک روی قطعات برای مشخصات.
۲. **شوروم:** انتخاب ایستگاه‌ها/محصولات.
۳. **ویرایشگر:** درگ اشیاء روی صفحه زمین.
۴. **بازی:** انتخاب هدف و تعامل.

## پیاده‌سازی (R3F)

```tsx
<mesh
  onPointerOver={(e) => { e.stopPropagation(); setHover(true); }}
  onPointerOut={() => setHover(false)}
  onClick={(e) => { e.stopPropagation(); onSelect(id); }}
>
```

برای هات‌اسپات‌های کوچک از مش‌های hit نامرئی بزرگ‌تر استفاده کن و هنگام unmount نشانگر/hover را بازنشانی کن.

## خطاهای رایج

- هات‌اسپات خیلی کوچک برای لمس
- محتوای فقط-hover بدون معادل کیبورد/لمس
- فراموشی `stopPropagation`
- raycasting در هر فریم روی صحنه عظیم وقتی رویدادها کافی‌اند
- وضعیت انتخاب‌شده فقط با رنگ نشان داده شود

## دسترس‌پذیری

یک فهرست DOM از همان هات‌اسپات‌ها بده. کاربران کیبورد باید بتوانند هر شیء را انتخاب کنند و جزئیاتش را بخوانند. Canvas به توصیف دسترس‌پذیر و جایگزین غیر-canvas برای محتوای حیاتی نیاز دارد.

## کارایی

انتخاب رویدادمحور R3F برای UI عادی کارآمد است. برای درگ/hover پیوسته، throttle کن و اشیای تست‌شده را محدود کن.

## کی استفاده کنی / نکنی

برای تعامل در سطح شیء استفاده کن. از این‌که تنها راه دسترسی به اطلاعات ضروری هدف‌های ریز canvas باشد پرهیز کن.

## نکات کلیدی

- پرتو = دوربین از میان اشاره‌گر.
- Hover پیش‌نمایش می‌دهد؛ کلیک قطعی می‌کند.
- ناحیه hit می‌تواند از نشانگر بصری بزرگ‌تر باشد.
- جایگزین‌های DOM برای محتوای مهم اجباری‌اند.

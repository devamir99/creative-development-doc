# شیدرها، گذار صفحه و کارایی

## اول ببین

<ShaderPlayground />

<PerformancePlayground />

<PageTransitionPlayground />

پنل شیدر یک جایگزین CSS برای ایده هسته است: **رنگ از موقعیت، زمان و پارامترها محاسبه می‌شود**. GLSL واقعی همان محاسبه را به‌ازای هر vertex/fragment روی GPU اجرا می‌کند.

## مدل ذهنی شیدر

| مرحله شیدر | کار |
|---|---|
| Vertex shader | رأس‌ها را جای می‌دهد؛ داده را جلو می‌فرستد |
| Fragment shader | رنگ هر پیکسل/fragment را محاسبه می‌کند |
| Uniform | پارامتر سراسری از CPU (زمان، ماوس، رنگ) |
| Attribute | داده به‌ازای رأس (موقعیت، UV، نرمال) |
| Varying | داده درون‌یابی‌شده بین مراحل |
| UV | مختصات دوبعدی روی سطح |

```glsl
uniform float uTime;
varying vec2 vUv;

void main() {
  float wave = sin(vUv.x * 10.0 + uTime) * 0.5 + 0.5;
  gl_FragColor = vec4(wave, vUv.y, 0.8, 1.0);
}
```

نحو بین نسخه‌های GLSL و تکه‌های شیدر Three.js فرق می‌کند؛ همیشه نسخه‌ای که راه‌اندازی‌ات استفاده می‌کند را چک کن.

## چرا شیدرها مهم‌اند

شیدرها گرادیان‌های واکنش‌گر به هندسه، اعوجاج، نویز، سطوح شبیه سیال، نورپردازی سفارشی، اثرهای تصویر، و زبان‌های بصری ناممکن با CSS تخت را ممکن می‌کنند.

## معماری گذار صفحه

۱. کاربر ناوبری را تریگر می‌کند.
۲. وضعیت پوشش/گذار وارد می‌شود.
۳. مسیر/محتوا درحالی‌که پوشیده یا crossfade است عوض می‌شود.
۴. صفحه جدید آماده است و فونت/تصاویر پایدارند.
۵. با همان زبان حرکت آشکار کن.

هرگز نگذار گذار بارگذاری خراب را پنهان کند. آمادگی محتوا را اندازه بگیر.

## بودجه کارایی

| هزینه | مراقب باش |
|---|---|
| JavaScript bundle | صحنه‌های سه‌بعدی/شیدر را lazy-load کن |
| GPU fill rate | اثرهای post تمام‌صفحه و DPR |
| Draw calls | مش‌ها/متریال‌های یکتا زیاد |
| Textures/models | فشرده‌سازی و استفاده مجدد |
| Animation loops | خارج از صفحه/مخفی را pause کن |
| Layout animation | `transform`/`opacity` را ترجیح بده |

## کاربردهای عملی

۱. **پس‌زمینه هیرو شیدر:** گرادیان نویز رانده‌شده با ماوس/زمان.
۲. **اعوجاج تصویر:** fragment shader روی hover/اسکرول UV را خم می‌کند.
۳. **wipe صفحه:** یک لایه تأکید می‌پوشاند، مسیر عوض می‌شود، آشکار می‌کند.
۴. **درخشش محصول:** متریال emissive به‌علاوه bloom مهارشده.

## استراتژی پیاده‌سازی

با متریال‌های داخلی شروع کن. فقط وقتی نیاز بصری روشن است `onBeforeCompile` یا ShaderMaterial اضافه کن. uniformها را typed نگه دار و متریال/هندسه را dispose کن.

## خطاهای رایج

- نوشتن شیدر قبل از فهم UV و نرمال
- اثر تمام‌صفحه روی هر بخش
- گذار صفحه‌ای که ناوبری را برای تزئین به تأخیر می‌اندازد
- بدون fallback وقتی WebGL نیست
- DPR بدون سقف روی نمایشگرهای چگال

## دسترس‌پذیری

حرکت شیدر می‌تواند شدید باشد. حرکت کاهش‌یافته را رعایت کن، از چشمک پرهیز کن، و هرگز اطلاعات ضروری را فقط در اعوجاج متحرک رمز نکن.

## کی استفاده کنی / نکنی

شیدرها را برای سطوح امضا و اثرهای real-time استفاده کن. برای کارت‌های عادی، پس‌زمینه متن، و محتوایی که کاربر باید پیوسته بخواند پرهیز کن.

## نکات کلیدی

- Fragment shader = رنگ به‌ازای پیکسل.
- Uniform تعامل/زمان را به GPU وصل می‌کند.
- کارایی محدودیت خلاقانه است، نه فکر بعدی.
- گذار باید آمادگی را آشکار کند، نه هرج‌ومرج را پنهان.
